# applyloop — job-application pipeline

This directory is the user's new-grad application system. Two entry points:

- `/scrape [24h|3d|... | ingest <file> | rebuild]` — scrape **and** ingest:
  pulls the day's LinkedIn postings, then filters, buckets, appends to
  `jobs.csv`, rebuilds `data/board.json`, and reports. Also owns ledger
  maintenance (`scripts/update_row.py` verbs). Manual: `agents/DAILY_SCRAPER.md`.
- `/batch <scope, in the user's own words>` — one application batch: select from board,
  probe, report, user decides, fill (stop before submit), bookkeeping.
  Manual: `agents/FILL_ASSISTANT.md`.

If you're working without either skill, read the manual for the role first.
Rules live in `rulebook.md`; form answers in `application_answers.md`; ATS
mechanics in `platform_notes.md`; facts in `experiences.md`. The application ledger is `jobs.csv` (write only via `scripts/update_row.py`
— never by hand); the candidate board `data/board.json` is a **derivative** of
it, regenerated by `scripts/board.py` from rows with `status=open` and empty
`low_fit`. Acting on a posting means setting its status, not editing the board.

Pipeline: `/scrape` → `enriched.jsonl` → `scripts/ingest.py` (dedup + filter +
bucket) → `jobs.csv` → `scripts/board.py` → `board.json` → `/batch`.
Classification rules live in `scripts/classify.py`, documented in
`rulebook.md` §5. Resume templates in `resumes/` are frozen —
tailored copies go to `application_records/`.

Why the pipeline is shaped this way: `DESIGN.md`. Setup: `SETUP.md`.

Multi-source scraper code (greenhouse / lever / ashby / workday / jobspy) is
archived under `scripts/legacy/` since the 2026-09-01 single-source refactor.
