# applyloop — two generations of a job-application system

**v2 is current** and lives in `v2/` as a sanitized public copy: four
skills (scout / saved-jobs-triage / job-apply / resume-tailor), ledger
verbs in `v2/bin/job.sh`, browser snippets, and templates for the four
personal files the skills read. To work on or adopt v2, start from
`v2/SETUP.md`; the design rationale is `v2/README.md`.

On the author's machine the *live* v2 system (with real ledger and
records) is a separate private workspace excluded by `.gitignore`; if a
`chrome_in_claude_assistant/` directory exists here, work there under its
own CLAUDE.md instead, and never commit it to this public repo.

---

**v1 below is archived in place** (still runnable, no longer used). Two
entry points:

- `/scrape [24h|3d|... | ingest <file> | rebuild]` — scrape **and** ingest:
  pulls the day's LinkedIn postings, then filters, buckets, appends to
  `jobs.csv`, rebuilds `data/board.json`, and reports. Also owns ledger
  maintenance (`scripts/update_row.py` verbs). Manual: `agents/DAILY_SCRAPER.md`.
- `/batch <scope, in the user's own words>` — one application batch: select from board,
  probe, report, user decides, fill (stop before submit), bookkeeping.
  Manual: `agents/FILL_ASSISTANT.md`.

Rules live in `rulebook.md`; form answers in `application_answers.md`; ATS
mechanics in `platform_notes.md`; facts in `experiences.md`. The ledger is
`jobs.csv` (write only via `scripts/update_row.py` — never by hand); the
board `data/board.json` is a **derivative**, regenerated by
`scripts/board.py` from rows with `status=open` and empty `low_fit`.
Acting on a posting means setting its status, not editing the board.

Pipeline: `/scrape` → `enriched.jsonl` → `scripts/ingest.py` (dedup +
filter + bucket) → `jobs.csv` → `scripts/board.py` → `board.json` →
`/batch`. Classification rules live in `scripts/classify.py`, documented
in `rulebook.md` §5. Resume templates in `resumes/` are frozen — tailored
copies go to `application_records/`. Why the pipeline is shaped this way:
`DESIGN.md`. Multi-source scraper code is archived under `scripts/legacy/`.
